# tools · 运行实例工具集

v0.4 规划顾问工具化的交付物。四个**零依赖**（仅用 Python 3 标准库）的命令行工具：

| 工具 | 作用 |
| :--- | :--- |
| `wf-verify` | 运行实例自洽性校验器——四文件结构、加权均分复算、跨文件数值一致性、嵌套检测、隐私红线扫描 |
| `wf-init` | 运行实例脚手架生成器——一键生成案例中立的运行目录与四文件骨架 |
| `selftest` | 工具与证据链一体化自测——18 项检查，一条命令跑完全部回归 |
| `scan_repo` | 仓库级可分发性扫描——隐私红线、真实院校名、死链、硬编码绝对路径 |

**判定依据只有落盘文件本体**，不采信任何自述结论。路径全部相对脚本所在位置解析，仓库克隆到任意路径即可运行。

---

## 快速开始

```bash
# 1. 生成一个运行实例
python3 tools/wf-init RUN_SYN102 --case-id SYN-UG-102 --materials <材料...>

# 2. 投放完成后校验
python3 tools/wf-verify RUN_SYN102

# 3. 全量回归自测（本地跑一次，等同 CI）
python3 tools/selftest.py --replay

# 4. 仓库可分发性扫描
python3 tools/scan_repo.py
```

## wf-verify · 自洽性校验器

```bash
python3 tools/wf-verify <运行目录> [选项]
```

| 选项 | 说明 |
| :--- | :--- |
| `--materials FILE[,FILE...]` | 指定用于均分复算的学业材料（默认自动发现学分表最全者） |
| `--denylist FILE` | 额外敏感词/真实院校黑名单，每行一条 |
| `--case-limit N` | `CASE.md` 软上限字节数（默认 10000） |
| `--json` | 输出机器可读 JSON |
| `--strict` | WARN 也计入失败 |
| `--quiet` | 仅输出 `PASS` / `FAIL` |

**退出码**：`0` = 通过；`1` = 存在 ERROR（或 `--strict` 下存在 WARN）。可直接接入 CI。

### 检查项

| 编号 | 级别 | 检查内容 | 依据 |
| :--- | :---: | :--- | :--- |
| E001/E002 | ERROR | 四文件缺失 / 为空 | 规范四文件状态树 |
| E003 | ERROR | `CHECKPOINT.md` 超过 4,000 字节硬上限 | AGENTS.md 第 2 条 |
| W001 | WARN | `CASE.md` 超过软上限（默认 10,000 B） | AutoRun03 复核报告口径 |
| E004 | ERROR | 声明均分与**加权均分复算值**不符 | 量表第 1、4 项 |
| E005 | ERROR | 均分 / R1 / R2 跨文件数值漂移 | 量表第 10 项「无跨轮次数字漂移」 |
| E006/E007 | ERROR | `CHECKPOINT` 嵌套他文件正文 / 内部长块自重复 | 历史真实缺陷（4572 B 嵌套） |
| E008 | ERROR | `CHECKPOINT` 缺少指向其余文件的指针 | 量表第 12 项「纯文件接续」 |
| E009 | ERROR | 检出真实个人数据或真实院校名 | AGENTS.md 第 1 条红线 |
| E010 | ERROR/WARN | EVIDENCE 证据表列数不足、局限列为空或占位符 | 量表第 15 项「全流程透明度」 |
| W002–W006 | WARN | 材料缺失、EVIDENCE 无来源编号、CHANGELOG 无日期条目、尚未声明均分 | 结构完整性 |
| W007 | WARN | CHANGELOG 存在空洞条目（无实质内容） | 审计轨迹有效性 |
| W008 | WARN | CASE.md 必备章节不完备（事实基线/学业测算/方案对比/结论下一步） | `01_Framework.md` 规范状态树 |
| W009 | WARN | CASE.md 未声明等级制课程的排除处置 | 量表第 2 项 |
| W010 | WARN | CASE 与 CHECKPOINT 的金额锚点无交集 | 量表第 10 项 |

### 加权均分复算

这是本工具的核心能力，直接对应量表第 1、2、4、5 项：

1. 解析材料中的「课程 | 学分 | 总评」markdown 表格；
2. **等级制非数值课程（Pass / 合格 / 免修…）自动排除在分母之外**；
3. 复算 `Σ(学分×分数) / Σ学分`；
4. 与 `CASE.md`、`CHECKPOINT.md` 中声明的均分值交叉核对；
5. 同时给出**算术均分**作为诊断——若文中出现算术均分值，即为误用未加权平均。

输出示例（对 AutoRun03 实际产物）：

```
── 加权均分复算 ──────────────────────────────────
  · 源材料：02_学业材料.md
  ·     高等数学  5.5cr × 56
  ·     线性代数  3.5cr × 78
  ·     Python程序设计  4.0cr × 84
  ·     概率论与数理统计  3.0cr × 72
  ·     专业英语与科技交流  1.5cr  合格 (Pass)  → 非数值，已排除
  · 分子 1133.0   分母 16.0（排除非数值 1.5 cr）
  · 加权均分 = 1133.0 / 16.0 = 70.8125%
  ℹ 算术均分 = 72.5%（若文中出现该值，说明用了未加权平均）
  ✓ CASE.md 均分声明命中复算值 70.81%
  ✓ CHECKPOINT.md 均分声明命中复算值 70.81%
```

### 均分表述兼容性

本工作流的不同时期用过三种写法，工具均可识别：

| 写法 | 出处 | 示例 |
| :--- | :--- | :--- |
| 百分数 | v0.2 起 | `加权均分 **70.8125%**` |
| 分数 | 早期 | `均分升至 82.50 分` |
| 裸数字 | v0.1 期 | `学分加权平均 = (5×52+…)/(5+4+3+2) = 990/14 = 70.714285…，约70.71分` |

**不会被误当作实绩均分**的语境：门槛（`≥ 80`、`要求…均分`）、情景（`升至`、`目标`、`情景 R1`）、教务系统/截图指标（`某学期平均分 77.20`——口径不同，不可与摘录加权混用）、算式中的分子分母。

## wf-init · 脚手架生成器

```bash
python3 tools/wf-init <运行目录> --case-id SYN-UG-102 \
  --materials 路径/01_初始背景.md 路径/02_学业材料.md \
              路径/03_两国模拟规则.md 路径/04_预算与规则更新.md
```

生成内容：

```
RUN_SYN102/
├── AGENTS.md                 案例中立的工作约定（取自 templates/Run_Template/）
├── 01_虚构学生初始资料.md     首轮材料
├── 02_学业材料.md             后续材料，按内容自动归位
├── 03_两国模拟规则.md
├── 04_预算与规则更新.md
├── CASE.md                   当前事实与决策基线骨架
├── EVIDENCE.md               来源与局限索引骨架
├── CHECKPOINT.md             极简导航锚点骨架（≤ 4,000 字节）
└── CHANGELOG.md              审计轨迹骨架
```

骨架中已内嵌四条核心纪律，Agent 无需额外说明即可正确落盘：

- `CASE.md` 是**唯一事实源**，其他三份文件只做引用；
- 不擅自换算 GPA / 百分制 / 国外绩点；**目标成绩不得当作实绩**；
- `CHECKPOINT.md` 硬限 4,000 字节，**严禁嵌套旧全文**；
- 未提供的信息一律记为「未知」，不得脑补。

> **安全约束**：`wf-init` **不会**拷入任何答案卡、标准核对答案或评分量表——那会污染弱引导测试。

## selftest · 一体化自测

```bash
python3 tools/selftest.py [--replay]
```

一条命令跑完全部回归（17 项，`--replay` 时 18 项）：

| 组 | 检查 |
| :--- | :--- |
| **证据链完整性** | AutoRun03/AutoRun02 的 `input_integrity`；PRE/FINAL 阶段快照 manifest；v0.3 `MANIFEST.json`；v0.3 投放材料与 v0.2 源逐字节一致；v0.3 评测设计与 v0.2 一致 |
| **基线判定** | AutoRun02/03 必须全绿；AutoRun01 必须命中已知历史缺陷（`CHECKPOINT` 4,572 B 超限） |
| **阴性用例** | 7 类破坏必须被检出并报 ERROR（夹具在临时目录生成，不入库） |
| **重放幂等** | `--replay`：重跑 `run_autorun03.py` 后产物必须逐字节不变 |

## scan_repo · 仓库级可分发性扫描

```bash
python3 tools/scan_repo.py
```

本产品库要公开分发给第三方顾问与开源评测，因此持续检查四件事：

1. **隐私红线**——任何文件都不得出现真实个人数据模式（手机号 / 身份证 / 学号 / 银行卡）；
2. **真实院校名**——只允许作为**反面示例**出现在治理文档（`AGENTS.md`、量表方案）中，**绝不**允许出现在任何 `simulations/` 产物内；
3. **死链**——全部 markdown 相对链接必须可达；
4. **硬编码绝对路径**——操作型文档不得写死本机路径；仅历史存档与决策/日志记录中的可追溯引用被豁免。

工具自身的黑名单与阴性夹具（`tools/wf_core.py`、`tools/selftest.py`）按设计含真实校名与学号模式，已显式豁免。

## 持续集成

`.github/workflows/verify.yml` 在 **push / PR / 手动触发** 时执行五步：

| 步骤 | 内容 |
| :--- | :--- |
| 1 | `tools/selftest.py` —— 工具与证据链自测 |
| 2 | 重跑 `run_autorun03.py` 后 `git diff --exit-code` —— 重放产物必须零漂移 |
| 3 | `tools/wf-verify` 现行基线 `--strict` —— 必须 0 ERROR 且 0 WARN |
| 4 | 重跑 `build_delivery.py` 后 `git diff --exit-code` —— 投放包生成器幂等 |
| 5 | `tools/scan_repo.py` —— 隐私、死链与绝对路径 |

> 该工作流在仓库推送到 GitHub 后自动生效；本地可用 `python3 tools/selftest.py --replay && python3 tools/scan_repo.py` 等价复现。

## 与 15 项量表的对应关系

`wf-verify` 可**自动判定**量表中的第 1、2、4、5、10、11 项及隐私红线（第 11 项）；其余各项（概念澄清、方案分析质量、政策推演、破局池等）**仍需人工/Agent 依 15 项量表逐项复核**——工具不替代复核，只是把可机械判定的部分自动化，把人的注意力留给判断题。

> **边界声明**：本工具判定的是**文件层面的自洽性**，不是规划建议的**正确性**。它无法判断一条政策推演是否合理，只能确认该推演在文件之间没有自相矛盾、其均分没有算错、其结构没有崩坏。
