# 面向多申请人的可复用留学规划工作流程 (Reusable Study Abroad Planning Workflow)

本项目是一套**解耦、模块化、可复用且高度严谨**的 AI 辅助硕士申请—海外就业—长期居留全流程规划体系。通过规范化的四状态文件结构、分步引导协议与标准化评测指标，确保不同背景申请人在多轮交互与跨 Agent 工具接续中，均能获得精准、自洽、且具前瞻抗风险能力的规划方案。

---

## 核心设计理念与架构

### 1. 核心理论：三阶段递进模型
- **阶段一：学业与背景现状精算**（学分加权均分、非数值课程隔离、不及格在档与重修提分测算、先修课缺口诊断）；
- **阶段二：多维约束交叉过滤**（预算全口径台账、语言学习成本与排期、意向国院校梯度匹配）；
- **阶段三：毕业后长效发展衔接**（工签法定条件与时效、工签对居留政策缺口自识别、前瞻政策冲击压力测试）。

### 2. 状态架构：四核心文件解耦
每一个规划会话运行实例（如 `Run_Template/`）均遵循四文件架构，**规范命名以本节为准**：
- `CASE.md`：当前事实与决策基线（背景、课程实绩、已确认/未确认预算、方案矩阵、成本与移民链、已接受决定）；
- `EVIDENCE.md`：来源与局限索引（每条主张的来源 ID、支撑范围、局限、模拟日期）；
- `CHECKPOINT.md`：极简上下文锚点（严格 $\le 4,000$ 字节，杜绝递归膨胀，仅包含当前阶段、核心数字、关键断点与下一步指令）；
- `CHANGELOG.md`：审计轨迹（多轮收发记录、决策节点与更新追踪）。

> **单一事实源**：同一事实以 `CASE.md` 为当前值，其余三份文件只做引用，不做平行叙述。
> **命名历史**：`simulations/` 下 v0.1–v0.3 冻结基线保留原始文件名与哈希记录，不追溯重命名。概念层旧表述（学生画像/选校进展/会话日志）的归位映射见 [`01_Framework.md` 第二节](01_Framework.md)。

### 3. 数据隔离与隐私保障
本工作流产品库**100% 采用合成数据与虚构案例（如松岚/澄湾/兰泽/沧澜等法条夹具）**，完全杜绝任何真实个人的档案、成绩单或隐私数据，具备完全的代码开源与产品化交付属性。

## 快速上手与评测验证

### 1. 运行现行弱引导自动基准测试 (AutoRun03)
在 `simulations/规划流程模拟包_v0.2/` 目录下：
```bash
python3 run_autorun03.py
```
该脚本将基于 `SYN-UG-102` 弱引导案例，自主完成加权均分、等级制课程隔离、重修情景建模、工签居留缺口发现与前瞻政策冲击应对，全过程捕获转录与快照并输出 15/15 指标独立复核报告。

> **可移植性**：脚本以**自身所在目录**定位包根（`WF_AUTORUN03_BASE` 可覆盖），仓库克隆到任意路径后均可直接运行，无需依赖固定绝对路径。

> **方法学提示**：`run_autorun03.py` 是**确定性重放器**——`CASE/EVIDENCE/CHECKPOINT` 正文以硬编码断言写入脚本，脚本本身不实际调用 LLM。15/15 是「产物 + 转录」的独立复核判定；实时智能体执行仅存在于 2026-10-28 的原始 AutoRun03 会话。

### 2. 外部客户端人工投放测试（v0.3 双版本投放包）

`simulations/规划流程模拟包_v0.3/` 提供两种投放形态，按目标客户端能力二选一：

| 形态 | 适用客户端 | 投放包 |
| :--- | :--- | :--- |
| **A · 文件读写型** | Claude Code、Codex CLI、Gemini CLI 等能读写本地目录者 | `Run_Template/03_外部投放包_文件读写版.md` |
| **B · 纯粘贴手动保存型** | ChatGPT、Claude 网页版、豆包、Kimi 等无文件能力者 | `Run_Template/04_外部投放包_纯粘贴手动保存版.md` |

两种形态共用同一套 SYN-UG-102 投放材料（`分轮投放_SYN102/`）与同一套六轮提示词，因此结果可横向对比。投放完成后，用 `评测设计_SYN102/04_外部投放结果记录表_SYN102.md` 记录观测元数据与 15 项复核判定。

> **独立复核纪律**：评分**不得**由被测 Agent 自行给出。必须依据落盘文件本体与各轮原始回复逐项核对；未实际投放的项目填「未测试」，不得填「通过」。

### 3. 运行实例校验与脚手架（v0.4 工具化）

```bash
# 校验一个运行实例（依据落盘文件本体判定，退出码可用于 CI）
python3 tools/wf-verify simulations/规划流程模拟包_v0.2/AutoRun03

# 生成一个全新运行实例
python3 tools/wf-init RUN_SYN102 --case-id SYN-UG-102 --materials <材料...>
```

`wf-verify` 可机械判定四文件结构、`CHECKPOINT` 体积硬上限、**加权均分复算**（自动排除等级制课程）、跨文件数值漂移、历史全文嵌套与隐私红线；其余判断题仍需按 15 项量表人工复核。详见 [`tools/README.md`](tools/README.md)。

### 4. 持续验证

```bash
python3 tools/selftest.py --replay   # 证据链 + 基线 + 阴性用例 + 重放幂等
python3 tools/scan_repo.py            # 隐私红线、真实院校名、死链、硬编码绝对路径
```

仓库另含 [`.github/workflows/verify.yml`](.github/workflows/verify.yml)，在推送到 GitHub 后于每次 push / PR 自动执行上述校验、重放幂等与投放包生成器幂等检查。

### 数据合规（重要）

本仓库**全部案例数据均为合成夹具**，可安全公开与分发：

- 学生一律使用代号（`SYN-UG-101` / `SYN-UG-102` / 李同学）；
- 院校一律虚构（海岚大学、松岚大学、兰泽应用大学、沧澜技术学院）；
- 目标国别一律虚构（松岚国、澄湾国、兰泽国、沧澜国）；
- 法规、签证与居留条款均为虚构夹具，**不构成任何现实法律或政策建议**。

唯一的真实世界内容是 `docs/真实官方来源核验报告_三项关键主张.md` 中的加拿大 IRCC PGWP 政策——那是**公开政策信息**，用于示范「主张须有官方来源支撑」的审计方法。

> 使用者若基于本仓库生成交付物，须自行确保未引入真实申请人的个人数据。

### 贡献建议

1. **先读** `AGENTS.md`（治理规约与红线）与 `01_Framework.md`（理论体系与规范状态树）；
2. **改代码前先跑** `python3 tools/selftest.py --replay && python3 tools/scan_repo.py` 建立基线；
3. **不要修改** `simulations/` 下 v0.1–v0.3 的基线产物、快照、manifest 与输入材料——它们是哈希证据链；
4. 新增运行实例一律用 `python3 tools/wf-init` 生成，四文件规范名为 `CASE / EVIDENCE / CHECKPOINT / CHANGELOG`；
5. 提交前确保 CI 五步全绿（自测 → 重放幂等 → 基线校验 → 生成器幂等 → 仓库扫描）。
